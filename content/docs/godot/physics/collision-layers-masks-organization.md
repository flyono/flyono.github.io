## 概述

在 Godot 引擎游戏开发中，对象交互——尤其是**碰撞检测** ——是不可避免的。“玩家不应该穿墙”，“敌人的攻击应该只击中玩家，而不是其他敌人”，“只有拥有特定钥匙的玩家才能打开某些门”……如果仅仅依靠嵌套的 `if`语句来管理这些复杂的规则，代码很快就会变得难以维护。

Godot 提供了一个优雅的解决方案：强大的**碰撞层**和**碰撞遮罩**系统。

本文通过具体场景和代码示例解释了这两个概念——这两个概念起初会让很多开发人员感到困惑。

## 为什么需要碰撞层/遮罩？

在小型原型中，由于物体类型较少，简单的碰撞检测可能就足够了。然而，随着项目规模的扩大，就会出现以下需求：

- **性能优化** ：让每个物体都与其他所有物体进行碰撞检测会浪费 CPU 资源。玩家需要与金币碰撞，但金币不需要与墙壁碰撞。缩小碰撞检测范围可以提升整体游戏性能。
- **声明式设计** ：在检查器中声明“什么”与“什么”发生冲突，而不是在代码中声明，可以使逻辑更容易理解。
- **复杂交互实现** ：只有在特定条件下才会发生的交互（例如，只有在能量提升时才能击败敌人）无需使代码复杂化即可实现。

## 基本概念：图层-Layer和蒙版-Mask的作用

在 `CollisionObject2D`/ `3D`（ `Area2D`、 `CharacterBody2D`、 `RigidBody2D`等）的检查器中，您会在 `Collision`部分找到 `Layer`和 `Mask`选项。准确理解这两个角色是第一步。

- **图层-Layer**：一个写着“ **我在这里** ” **的标签，** 指示对象所属的物理组。
- **掩码-Mask** ： **列出您要查找的内容** ，表示“ **我想与这些对象交互** ”。指示此对象要检测哪些图层的对象。

`PhysicsBody`对象之间发生碰撞只需**单方兴趣**即可。物体 A 与物体 B 发生碰撞， **以下**任一条件均成立：

1. 对象 A 的**蒙版**选中了对象 B 的**图层** 。
2. 对象 B 的**蒙版**选中了对象 A 的**图层** 。

>“只要一方在监视另一方，就会发生冲突”是关键所在。它不一定是双向的。

>**注意** ：双向遮罩设置仅在“ **双方都希望检测到对方** ”时才需要。例如，如果玩家和敌人都希望检测到对方的存在，则需要在双方都设置遮罩。但是，如果只有一方的遮罩检测到另一方的图层，则会发生物理碰撞（阻挡移动）。

## 第一步：给图层命名

图层和蒙版内部实际上是位标志（数字），但靠人脑记忆“第 3 层是敌人”既低效又容易出错。务必在项目设置中清晰地命名每个图层。

1. 从菜单中打开“项目”→“项目设置”。
2. 从左侧树状菜单中选择“图层名称”→“2D 物理”或“3D 物理”。
3. 给每一层都起特定的名字，例如"player," "enemy_body," "enemy_attack," "world," "item."

这一小小的努力大大提高了后续的开发效率。

## 实际案例：具体设置场景

让我们以一款典型的动作游戏为例，来看一些具体的设置。

| 对象                            | 图层（我在这里）       | 掩码（我想检测这些）                                                                                                  | Notes  笔记     |
| :---------------------------- | :------------- | :---------------------------------------------------------------------------------------------------------- | :------------ |
| **Player (CharacterBody2D) ** | `player`       | `world`, `enemy_body`, `item`, <br>`enemy_attack`  <br>`world`、 <br>`enemy_body`、<br>`item`、 `enemy_attack` | 与所有主要对象交互     |
| **Enemy (CharacterBody2D)**   | `enemy_body`   | `world`, `player`  <br>`world`， `player`                                                                    | 敌人之间不会碰撞，忽略物品 |
| **Enemy Attack (Area2D) **    | `enemy_attack` | `player`                                                                                                    | 仅检测是否对玩家造成伤害  |
| **World (StaticBody2D)**      | `world`        | `player`, `enemy_body`  <br>`player`， `enemy_body`                                                          | 阻挡玩家和敌人的身体    |
| **Coin (Area2D)**             | `item`         | `player`                                                                                                    | 仅由玩家收集        |

这种设置可以实现：

- **玩家** ：被墙壁阻挡，接触敌人，拾取物品，受到敌人攻击。
- **敌人** ：沿墙壁移动，追逐玩家，但不干扰其他敌人、物品或自身的攻击检测。
- **敌方攻击区域** ：仅检测玩家进入，并发出信号。不受墙壁或其他物体的影响。

## 通过代码实现动态控制

图层/蒙版的真正价值在于通过脚本动态更改它们。我们来看一个实现示例：玩家拾取“幽灵”物品后，可以在一段时间内穿过敌人。

```gdscript
# player.gd

func _ready():
    # 初次与敌方单位（敌方躯体）发生碰撞
    set_collision_mask_value(3, true) # 假设第3层为“敌方身体”

func _on_ghost_item_picked_up():
    # 禁用与敌人的碰撞
    set_collision_mask_value(3, false)
    print("Ghost mode activated! Passing through enemies.")

    # 5秒后恢复的计时器
    $GhostTimer.start(5.0)

func _on_GhostTimer_timeout():
    # 重新开启与敌人的碰撞判定
    set_collision_mask_value(3, true)
    print("Ghost mode ended.")
```

使用 `set_collision_mask_value(layer_number, enabled)`可以根据游戏状态灵活地更改碰撞规则。

## 常见错误和最佳实践

以下是初学者常犯的错误以及避免这些错误的最佳实践：

| 常见错误                                  | 最佳实践                                                                                                                                                     |
| :------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **未命名图层**                             | **一定要给它们命名。** 这对于团队发展和长期维护至关重要。                                                                                                                          |
| **混淆 `Area2D`和 `PhysicsBody`检测条件**    | **如果一个掩码包含另一个掩码的图层** （即满足“或”条件），则会发生 `PhysicsBody`碰撞。类似地，当 `Area2D`的 `Mask`检测到另一个掩码的 `Layer`时，也会发出类似 `body_entered`信号。但是， **如果两者都需要进行碰撞检测** ，则两者都需要设置掩码。 |
| **赋予一个对象多个角色**                        | 分别进行检测。例如，将敌人的“身体”和“攻击范围”拆分为不同的对象（ `CharacterBody2D`和 `Area2D`），每个对象都具有相应的图层/蒙版设置。                                                                       |
| **`if`对 `move_and_slide()`结果进行复杂的过滤** | 在 `move_and_slide()`函数报告与图层/遮罩的不必要碰撞之前，先将其排除。保持代码简洁。                                                                                                     |
| **无需规划即可使用全部 32 层**                   | 首先分配主要类别（玩家、敌人、世界……），后续图层用于辅助检测（小地图、相机触发器……）。建立大致规则。                                                                                                     |

## 性能考量

Godot 的物理引擎经过高度优化，但在处理成千上万个物体时，碰撞检测可能会成为瓶颈。

- **最小化掩码** ：对象掩码中的层数越多，意味着检测目标越多，负载越高。仅启用真正必要的交互。
- **保持物理进程轻量级** ： `_physics_process`中的繁重处理会影响整体物理性能。
- **禁用不必要的对象** ：对于屏幕外的敌人或对象，禁用 `CollisionShape`（ `$CollisionShape2D.disabled = true`）或从树中移除，以完全排除在物理计算之外。

## 后续步骤

掌握碰撞层/遮罩之后，学习以下相关主题，以实现更高级的游戏机制：

- **`Area2D`/ `Area3D`**：非常适合检测物体进入/离开而无需物理碰撞。可用于检测范围、损坏区域、对话事件触发器等。
- **光线投射** ：使用 `RayCast2D`/ `RayCast3D`节点或 `PhysicsDirectSpaceState`，向特定方向投射光线以检测第一个被击中的物体。
- **物理材质** ：在 `PhysicsBody`或 `Area`上设置 `PhysicsMaterial`可以精细控制摩擦系数和弹跳系数。

## 总结

碰撞层和遮罩是 Godot 中物理交互的基础，它们构成了一个极其强大且可扩展的系统。记住，“层”是一个名称标签，“遮罩”是你正在寻找的内容列表，以及“如果一个遮罩看到另一个遮罩的层，则发生碰撞”的 OR 条件规则——接下来就是练习了。


在检查器中以声明式方式定义图层关系，仅在需要时才使用脚本进行动态控制。遵循此原则将使您的项目更简洁、性能更高且更易于管理。首先在项目设置中为图层命名。
