> "编辑器里跑得好好的，导出后是黑屏。" "只有某一个平台会报错。" 游戏基本做完、该交到玩家手里时，最后一步导出(构建)经常撞上意外的墙。知道**导出怎么工作、各平台有什么脾气**，这类最后一公里的问题大多可以避开。

本文覆盖把 Godot 项目可靠发到 Windows、macOS、Android 和 Web 所需的一切: 导出模板和 PCK 怎么配合、第一次导出的步骤、最容易踩的坑(大小写敏感、Web 头)、体积优化，以及发售前检查清单。

## 导出如何工作: 模板与 PCK

搞懂导出只需两样: **导出模板(export templates)** 和 **PCK**。

**导出模板**就是按平台编好的 Godot 引擎本体。你的项目(场景和脚本)骑在模板上，变成可执行的东西。

- **版本必须一致**: 编辑器和模板必须是**完全相同**的版本(对不上就无法导出)
- **Debug 与 Release**: 模板里两种都有，导出时选。发给玩家用 **Release**

**PCK** 是把项目的场景、脚本、资源打成一个文件。可以选择和可执行文件**分开**，或**嵌入**进去。

| PCK 处理 | 优点 | 缺点 | 典型用途 |
| --- | --- | --- | --- |
| **分开**(默认) | 可执行文件小，补丁好发 | 要分发多个文件 | PC |
| **嵌入** | 只发一个文件 | 可执行文件更大 | Web、移动 |

## 实践: 第一次导出(桌面再到 Web)

独立游戏上 itch.io、给 Windows 发免费版、上架手机应用: 第一步都一样。标准路线是先导出 **桌面(Windows)**，再做 **Web(itch.io)**。各平台的步骤同一套流程。

1. **拿模板**: `Editor > Manage Export Templates`，下载当前 Godot 版本对应的模板
2. **加预设**: `Project > Export > Add`，选要发的平台(例如 Windows Desktop)
3. **核对设置**: 确认主场景、图标、以及是 Release 还是 Debug
4. **导出**: 用 "Export Project" 选输出位置，写出构建

桌面版能跑之后，在同一项目里加 **Web** 预设，导出，上传到 itch.io 就能在浏览器里玩。先把一个平台从头到尾跑通，后面的平台会好跟得多。

有两个要点。

- **永远测真正导出的构建**: 编辑器能跑和导出能跑是两回事。尤其是保存(`user://`)在导出后行为可能不同，务必拿真实构建验一遍存档读写。详见《实现保存/加载系统》。
- **先打通一个再加平台**: 不要一次瞄准所有平台。把 Windows 这种顺手的目标推到能独立运行。隔离错误会容易得多。

## 各平台要点与陷阱

### 最大的坑: 大小写敏感

**这是 Windows 开发者踩得最多的错。** Windows 不区分文件名大小写，但 **Linux 和 Android 非常严格**。

代码写 `res://Assets/Player.png`，实际文件是 `res://assets/player.png`: Windows 编辑器里能跑，**一导出就加载失败**。修法很简单: **文件名统一成小写 `snake_case`**。

### Windows / macOS

桌面最简单。Windows 可以用 `rcedit` 嵌入图标和版本信息。macOS 分发可能需要苹果的 **公证(notarization)**。

### Android

Android 是设置最多的平台。

- **SDK / JDK**: 在 `Editor Settings > Export > Android` 里设路径。**Godot 4.x 需要 JDK 17(或 21)**(3.x 用的是 JDK 11)
- **AAB vs APK**: Google Play 建议 AAB。APK 更适合测试和直接分发
- **报错路标**: `No Android SDK found` 是 SDK 路径没设，`apksigner not found` 是没装 build-tools

### Web

Web 容易碰到，但有一个**跟服务器环境绑在一起的坑**。导出时开了线程，浏览器需要 `SharedArrayBuffer`，服务器就必须带 **COOP / COEP 头**。

```
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

- **itch.io**: 勾一个 SharedArrayBuffer 复选框就行
- **自己的服务器**: 把上面两个头加进配置
- **关掉线程**: 导出设置里关掉 threads，构建就能在没有这些头的情况下跑(可能影响性能)

## 优化构建体积

分发体积大会让下载变慢，Web 上首次加载也会慢。按影响从大到小下手。

| 手法 | 做法 | 影响 |
| --- | --- | --- |
| **资源过滤** | 在导出设置的 Resources 页只包含需要的文件 | 高 |
| **贴图压缩** | 在 `.import` 设置里开启 VRAM 压缩 | 高 |
| **音频质量** | 降低音乐和音效的码率 | 中 |

**剔掉没用的资产**收益特别大。发售前检查原型期的资源是不是还躺在项目里。

发售前的帧率和卡顿问题，见《在 Godot 中稳定 FPS: 帧率管理与优化》。

## 发售前检查清单

导出前确认这四件事。盖住它们，大多能避免"发出去跑不起来"。

| 检查 | 细节 |
| --- | --- |
| **大小写敏感** | 资源路径和真实文件名(含大小写)一致吗? |
| **外部工具路径** | Android SDK、JDK、rcedit 路径对吗? |
| **关掉 Debug** | Release 构建的 "Export With Debug" 是 OFF 吗? |
| **主场景** | 启动场景设对了吗? |

## 小贴士

- **尽早试一次导出**: 如果第一次导出就在发售前夕，大小写对不上这类问题会一起爆发。**开发早期就打通一次导出**能省后面的苦。
- **`.res` 与加密**: 发售版考虑用二进制 `.res` 代替文本 `.tres`，需要的话再加密。详见《创建和使用自定义资源》。
- **按平台回头看操作**: Web 和移动会改掉前提(没有键盘、竖屏、触摸输入)。对着真正要发的目标核一遍输入处理。

## 总结

- 导出就是把**项目**放上**版本一致的模板**再写出去。发给玩家用 **Release**
- **PCK** 按用途选分开(PC)或嵌入(Web、移动)
- 最大的坑是**大小写敏感**。文件名统一成小写 `snake_case`
- **Android** 需要 JDK 17 加 SDK/build-tools；**Web** 开线程时需要 COOP/COEP 头
- 发售前确认**大小写、外部工具路径、Debug 关掉、主场景**，并且永远**测真正导出的构建**

先把一次 Windows 导出打通，确认得到的 `.exe` 能独立启动。能交出去的那一刻，项目才从游戏变成已发布的作品。
